# Arize Ingestion — Validation (#56)

**Status: FUTURE-STATE dependency, fully BLOCKED. No live Arize instance exists — see §2.**

Validation record for
[#56 Validate Arize ingestion](https://github.com/rob-mckenna/foundry-otel-to-arize-demo/issues/56),
depends on #38 (OTLP export conformance).

## 1. Acceptance criteria under validation

1. For each synthetic batch sent, Arize's ingestion response (or ingestion log) confirms success
   with no rejected spans.
2. Span count sent equals span count visible in Arize for each batch.
3. Any ingestion failure is filed as a bug with the batch's synthetic trace IDs and the ingestion
   error/response code as evidence.

## 2. Why this is fully blocked

Same structural situation as #54: there is no deployed Arize instance (space/tenant) anywhere in
this project's history, no credentials, and no Function code producing real OTLP batches to send
in the first place (`src/telemetry-pipeline` is a placeholder — see corrected README, PR #121).
Every one of this issue's three criteria requires sending a real batch to a real Arize endpoint and
reading back a real ingestion response — none of which can happen without that deployment existing.

## 3. What exists and was reviewed: an OTLP conformance spec, not an ingestion test

[`docs/telemetry/otlp-export-conformance.md`](./../telemetry/otlp-export-conformance.md) (#38)
and its companion
[`tests/export/test_otlp_export_conformance.py`](./../../tests/export/test_otlp_export_conformance.py)
prove the *shape* of a synthetic 50-span OTLP batch is well-formed (parity, resource attributes, ID
round-tripping) — this is a necessary precondition for successful Arize ingestion (a malformed
batch would be rejected), but it is not the same as confirming Arize's actual ingestion endpoint
accepts it. No OTLP batch generated by this repo has ever been sent to a real Arize endpoint.

## 4. Sandbox limitation

No deployed Arize instance, no Function/OTLP-sending code, and no Python interpreter exist in this
session.

## 5. Validation checklist (to run once a deployed Arize space + Function/OTLP exporter exist)

- [ ] Send a known-count synthetic batch (reuse the #38 reference generator's batch, or a real
      Function-produced batch once it exists) to the live Arize OTLP ingestion endpoint.
- [ ] Capture Arize's ingestion response/log for that batch — confirm `success`, zero rejected
      spans.
- [ ] Query Arize (UI or API) for the batch's span count and compare against the sent count.
- [ ] Repeat for at least 2–3 batches of varying size to rule out a size-dependent silent-drop
      bug.
- [ ] Record a sent-count vs. received-count table in a `demo-validation.yml` entry.
- [ ] File a `bug-report.yml` (component: "Arize ingestion") for any mismatch, citing the batch's
      trace IDs and the ingestion error/response code — never raw span content.
